# POS連携（ダイニー / 新Uレジ）— B案＋A案の良いとこ取り

FWに乗らないPOS（ダイニー・新Uレジ）の売上/原価を、infomart自動化と同じ流れで
Googleスプレッドに取り込む。**Playwrightはログイン→「公式CSVエクスポート」までを自動化し、
画面の数字はスクレイプせず、ダウンロードした正規CSVを取り込む**（＝A案の安定＋B案の自動化）。
API/トークンがあるPOSはPlaywright不要でAPI直取りに差し替え可。

## 構成
- `pos_common.py` … 共通スキーマ・CSVパース・シート書込（重複排除つき）
- `dinii_sync.py` / `uleji_sync.py` … 各POSのログイン→CSVエクスポート→正規化→書込
- `.github/workflows/pos_sync.yml` … 毎月自動実行（締め後）

出力スキーマ（既存FW→シートと統一）：
`年月, 店舗名, 売上, フード原価, ドリンク原価, 客数, 備考, 取込日時, POS`

## 対象月の指定（埋め戻し）
ワークフローの `month` 入力、または引数で渡す。

```
（空）              先月ひとつ。毎月の自動実行はこれ
2026-08            単月
2026-05:2026-08    範囲（両端を含む）
2026-05,2026-08    とびとび
```

⚠️ **複数月でもログインは1回。** 12分のあいだに3回ログインしてOTPが弾かれた
実績があるので、「月数ぶんワークフローを回す」使い方はしないこと。
一度に指定できるのは24か月まで。

⚠️ **範囲・複数月のときダイニーは走らない。** ダイニー側は単月しか解さず、
範囲を渡すとそれを対象月として扱ってしまうため。

## セットアップ（credはSecretsに。チャット/コードに直書きしない）
GitHub → リポジトリ → Settings → Secrets and variables → Actions に登録：
- ダイニー（2欄ログイン）
  - `DINII_USER` … ログイン用**メールアドレス**
  - `DINII_PASS` … パスワード
  - `DINII_LOGIN_URL`（任意。既定 `https://dashboard.self.dinii.jp/`）
- 新Uレジ／USENレジ（**3欄ログイン**）
  - `ULEJI_COMPANY` … **企業コード**
  - `ULEJI_USER` … **担当者コード**
  - `ULEJI_PASS` … パスワード
  - `ULEJI_LOGIN_URL`（任意。既定 `https://pos.usen-regi.com/cms/login/init`）
- `TARGET_SHEET_ID`（書込先スプレッドID）と `GCP_SA_JSON`（サービスアカウントのJSON丸ごと）
  ※ infomart-bot SAはDrive容量枯渇の既知課題。書込先は個人アカ所有シートにSAを共有編集者で追加するのが安全。
  ※ SAを使わない場合は `TARGET_SHEET_ID` 未設定でローカルCSV出力に自動フォールバック（既存GAS取込運用向け）。

### 診断モード（スクショ無しでエクスポート導線を確定する）
ログイン欄は確定済み。残りの「売上レポート→CSV出力」の導線は、実行環境から実画面を出力させて詰める。
1. Actions → このワークフロー → **Run workflow** で `diag` に `1` を入れて実行。
2. ログイン直後の画面のスクショ・HTML・クリック候補・リンク・入力欄一覧が **artifact `pos-diag`** に上がる。
   同じ内容の要点は **ジョブログにも出力** される（artifactを開けない環境でも読めるように）。
   ※ このリポジトリは private なのでジョブログは外部に出ない。
3. その artifact を私（Claude）に渡せば、エクスポート導線と期間指定を確定してTODOを埋める。
   （＝管理画面のDevToolsを触らずに済む）
※ 診断モードはログインするだけで売上取得・シート書込は行わない（安全に導線だけ確認）。

## 新UレジのOTP対策 — (A)「定期メール送信/API」の調査結果（2026-09）

ログインは 企業コード/担当者コード/パスワード まで通るが、その後に**メール認証コード(OTP)**が挟まる。
ブラウザ自動化ごと回避できる経路があるかを先に調べた。**公開情報の範囲では、以下のとおり。**

| 経路 | 結論 | 根拠 |
| --- | --- | --- |
| 売上CSVの定期メール送信 | **見つからない** | ヘルプ/FAQに該当機能の記載なし。「日報機能」は店舗が手入力する営業報告であって売上データの自動配信ではない |
| 顧客が直接叩ける公開API | **見つからない** | 公開されているのは freee会計 / マネーフォワードクラウド会計 / 弥生 / ASPIT 等との**パートナー連携**。API仕様書は非公開 |
| 会計SaaS経由の自動エクスポート | **あり（唯一の非ブラウザ経路）** | マネーフォワードクラウド会計連携で「USENレジの売上データを毎日自動取得」。freee連携はレジクローズ時に売上/入出金/現金差異を自動取込 |

**評価**: (A)は「USENレジ単体では無い。ただし会計SaaSを経由すれば自動で外に出せる」。
ただし本件が欲しいのは**フード/ドリンク原価と客数**であり、会計連携が運ぶのは売上・入出金が中心。
原価・客数まで取れるかは連携先の仕様次第なので、**この経路だけでは要件を満たせない可能性が高い**。

**未確認（公開情報では詰め切れなかった点）** — USENサポートへの確認が必要:
1. 管理画面のOTPを、IP許可や信頼済み端末の登録で**省略できる設定があるか**
2. 売上/原価CSVを**定期メール送信する隠し設定**（代理店経由でのみ案内されることがある）
3. 会計連携の連携項目に**原価・客数**が含まれるか

→ 1が「できる」なら自動化は一気に安定する。まずここを問い合わせるのが最短。
回答が出るまでは (C) `storage_state` 再利用を暫定策として実装する想定（未着手）。

## 新UレジのOTP自動取得 — メールの設定

ログイン後に必ずメールで6桁の認証コードが要求される（画面に「この端末を記憶する」は無く、
省略できない）。そこで**実行しているプロセス自身がIMAPでメールを読みに行く**。
`uleji_sync.py` は「認証コード再送を押す → メールを読む → 入力 → 認証」まで実装済みで、
足りないのは下のSecretsだけ。

### 前提: サイボウズの証明書は不要
ガルーンは**メールサーバーではない**。別のメールサーバーにPOP/IMAPで繋いでいる
「閲覧画面」にすぎない。だからガルーンを経由せず、その**元のメールサーバーへ直接**
IMAPで繋げばよく、セキュアアクセスのクライアント証明書は関係なくなる。

サーバー名は ガルーン → 個人設定 → メール → メールアカウントの設定 → メールサーバーの
「詳細」に出ている **受信メールサーバー名** をそのまま使う（レンタルサーバーなら
`svXXXX.<事業者>.jp` の形。具体値はSecretsに入れるのでここには書かない）。

### Secrets
| Secret | 値 |
| --- | --- |
| `OTP_IMAP_HOST` | ガルーンに出ている受信メールサーバー名 |
| `OTP_IMAP_USER` | 受信メールアカウント（＝メールアドレス全体） |
| `OTP_IMAP_PASS` | そのメールアカウントのパスワード（ガルーンのログインパスワードではない） |
| `OTP_IMAP_PORT` | `993`（省略時も993） |
| `OTP_SUBJECT_HINT` | 任意。件名の絞り込み語（既定「認証コード」） |
| `OTP_FROM_HINT` | 任意。差出人の絞り込み語（既定 `usen-regi.com`） |

### 認証コードメールの形（実物で確認済み）
差出人 `no-reply@pos.usen-regi.com` ／ 件名「【USENレジ】認証コードのお知らせ」／
本文に「認証コード：（6桁）」。**有効期限は15分**なので、取得は再送を押してから行う。

**差出人で絞るのが要**。個人のメールボックスには他サービスの「認証コード」メールも
届くので、件名の語だけだと別サービスのコードを拾う。`tests/test_otp.py` で、
他サービスのメールを無視すること・古いメールを無視すること・差出人が違えば
件名が同じでも拾わないことを確認している（`python tests/test_otp.py`）。

### どのメールボックスを指すか
1. **（推奨）取込専用のメールアドレスを1つ作り、新Uレジの通知先をそれに変える。**
   読める範囲がOTPメールだけになる。公開リポジトリのSecretsに置く以上、
   万一の時に失うものを最小にしておく。
2. 本人のアドレスを直接指す。すぐ動くが、受信箱全体が読める状態になる。

どちらでも、このコードは**読むだけ**：`select(readonly=True)` + `BODY.PEEK[]` なので
既読フラグも立てず、削除も移動もしない。取得したコードはログに出さない（桁数だけ出す）。

## ローカル実行（PowerShell運用メモ）
- `&&` は使わない（`;` で連結）。日本語文字列を渡す時はbase64推奨。コマンドは1つずつ。
```
pip install playwright gspread google-auth pandas ; python -m playwright install chromium
$env:DINII_LOGIN_URL="..." ; $env:DINII_USER="..." ; $env:DINII_PASS="..."
python dinii_sync.py 2026-08
```

## 取り込み後
このシート（`POS売上`タブ等）を店長会サマリー生成時に読み、FW欠損店（ダイニー/Uレジ店）の
売上・原価を補完する。理論原価が未取込だった店（ひよこ・ちゃーちゃん・たいだい 等）の
不明ロス見かけ肥大も、これで実態に是正される。
